# video-director —— 视频制作前置链

> **定位**：`html-explainer` 之前的那一段。后者管「怎么把它做出来」，本技能管
> **「到底要做一个什么样的东西，以及它做出来会不会难看/单调/做不到」**。
>
> **一句话**：用户说「我想做个视频」，到这里结束时手里应该有一份**他自己点头的创作简报**，
> 而不是一句模糊的祈愿 + 一串替他拍板的选择。

---

## 0. 这个技能解决什么问题（先读，别跳过）

现有管线（`html-explainer` v2.0）的问题**不在执行，在入口**：

| 现有入口 | 字段 | 谁决定的 |
|---|---|---|
| `brief.json` | `topic / mood / pace / audience / aspect` —— **五个粗字段** | 没人问过用户，常常是 agent 从主题词猜的 |
| `consent.json` | 七项确认（theme/style/form/voice/duration/cover/render_channel） | 有闸门逼着问，但**问的是「选哪个」，不是「你想要什么」** |

后果就是你遇到的那三件事：
1. **动效单调** —— 因为「你想要什么节奏/什么运动密度」从来没被翻译成 `motion_intensity`、`pace`、运镜数量这些**机器能执行的参数**；
2. **图画草率** —— 因为「画面主体是什么、有几个元素、要不要运镜」在策划期是空的；
3. **弱模型下更糟** —— 自由发挥型指令（「做个有设计感的视频」）对弱模型近乎无效，必须落成**查表 + 候选 + 拍板**。

**本技能的核心资产是 `references/feeling-to-params.md`：把「高级感 / 别像 PPT / 要燃」这类话，翻译成管线真实吃的参数。** 这是治「提示词说不清」的命门。

## 1. 三阶段与入口（可单独调用）

```
用户一句模糊需求
      │
      ▼
【阶段 A · 策划】── 结构化访谈 → 感觉翻译 → 候选收敛 → 可行性判定
      │              产出：brief.json · consent.json · creative-brief.md（策划书）
      ▼
【阶段 B · 审查】── 自洽性 / 单调度(PPT 度) / 可行性 / 机械体检
      │              产出：review.md（分级问题 + 改法）
      ▼
【阶段 C · 优化】── 成片后复盘 → 写回 lessons.md → 下次默认更好
      │
      ▼
交给 html-explainer（阶段 0 起跑）
```

**★ 全程分段验收**：每生成一段就停下让你验收一段，前置不过不许进下一关。

```bash
python <skill>/scripts/accept.py --project . --list        # 看进度与下一关
python <skill>/scripts/accept.py --project . --show V2     # 看这关该验什么
python <skill>/scripts/accept.py --project . --pass V2 --note "..."
```

十五关全景（A1–A5 策划 / B1 体检 / V1–V9 制作）见 **`references/acceptance-protocol.md`**。

| 你说 | 走哪段 |
|---|---|
| 「我想做个视频，但说不清要什么样」 | **A**（完整访谈） |
| 「就这个方向，帮我快速定方案」 | **A 精简版**（轮 1+3，跳过参照锚定） |
| 「帮我看看这个分镜/简报行不行」 | **B 单独调用**（读现有 `brief.json` + `storyboard.md`） |
| 「这版出来会很单调吗 / 会不会像 PPT」 | **B** 的 §2 单调度体检 |
| 「每生成一段就让我验收一段」 | **`accept.py`** 全程把关（默认就该这样跑） |
| 「整条链路到底怎么走」 | **`references/pipeline-full.md`**（逐环节） |
| 「审美审查怎么做」 | **`references/aesthetic-review-layers.md`**（八层） |
| 「片子做完了，复盘一下」 | **C** |

## 2. 阶段 A · 策划（把感受变成参数）

**铁律：不许替用户拍板。** 每一轮只问关键项，**每项给 2–4 个候选让他挑**——
这不是礼貌问题，是**弱模型 + 用户说不清**这个组合下唯一可靠的收敛方式。

### 轮次表（照这个顺序走，别跳）

| 轮 | 目标 | 问什么 | 读 |
|---|---|---|---|
| **A1 意图** | 定「给谁看、在哪看、要什么反应」 | ① 看完你希望观众做什么/感觉什么 ② 发在哪（抖音/小红书/B站/内部分享/作品集）③ 一句话主题 | `references/interview-bank.md` §1 |
| **A2 参照锚定** | 定「像什么、不像什么」 | ① 有没有想「像」的片子/账号/品牌 ② **明确不想像什么**（防雷同）③ 三个形容词，不问抽象问具体 | `interview-bank.md` §2 |
| **A3 感觉翻译** | **核心**：把 A1+A2 翻译成参数 | 摆一张【参数表】让用户逐行确认/改（不给开放题） | **`references/feeling-to-params.md`** |
| **A4 硬约束** | 凑齐 `consent.json` 七项 | 时长/画幅/配音方案+音色/封面张数/渲染通道/配色/风格 | `interview-bank.md` §3 |
| **A5 可行性 + 拍板** | 「能不能做到」与「确认这就是你要的」 | 摆可行性结论 + 策划书，让用户签字 | `references/feasibility.md` |

### 各轮纪律

- **一轮一问，别把 15 个问题一次糊上去**——用户会答不全，等于没问。
- **永远给候选**。「你想要什么风格？」是坏问题；「A 瑞士网格 / B 胶片漏光 / C 故障艺术，哪个更像你要的？」是好问题。
- **用户说"你决定"时**：可以决定，但必须回报「我选了什么、为什么、代价是什么」，并留一次否决机会。
- **A3 是分水岭**：这一步之前是聊天，这一步之后是**可执行的规格**。若 A3 的表格用户改不动也挑不出，就说明 A1/A2 没问够，退回去重问，别硬推。

### 产出（三份，缺一不可）

| 文件 | 给谁用 | 内容 |
|---|---|---|
| `brief.json` | `style_director.py` 读 | `topic / mood / pace / audience / aspect` —— **补全版**，另可加 `director` 段承载更细的意图（管线忽略未知字段，安全） |
| `consent.json` | `gate_check.py` 读 | 七项 `{choice, decided_by:"user", at}` |
| `creative-brief.md` | **给人看** | 一页策划书：意图 / 参照 / 参数表 / 可行性 / 风险。这是用户能读懂并否决的那份 |

脚手架：

```bash
python <skill>/scripts/brief_init.py --project <项目目录> [--slug 名字] [--topic "主题"]
```

它生成三份骨架 + 打印访谈轮次清单，**不替用户填任何 choice**。

## 3. 阶段 B · 审查（出片前拦截）

**在写解说词之前跑，别等到渲染完。** 改动成本随阶段指数上升：简报期改一个词 = 0 成本，渲完再改 = 整片重来。

### B1 自洽性
`brief.json` / `consent.json` 内部与互相之间有没有打架。例：`mood:calm` 却选了故障艺术；`duration_sec:20` 却排了 12 场；亮底配色却没配亮底字幕皮肤。

### B2 单调度体检（对症你的"单调"）
这是本技能**最该被用起来**的一段。五条判据，逐条数字数：

| 判据 | 红线 |
|---|---|
| 风格数 | 全片 < 2 种 = 单调；> 4 种 = 花 |
| 同风格连场 | 连续 ≥3 场同一个 = 单调 |
| 运镜场次比 | **每场 ≥1 次可测运镜**（`slowPush`/`camTrack`/`whipPan`），低于 100% 就是 PPT 苗头 |
| 承接连律 | 相邻场**至少一个元素跨边界继续动**，全片承接数为 0 = 幻灯片 |
| 动效强度分布 | `motion_intensity` 全片方差过小（都 0.5）= 平；应有一条起伏曲线 |

**判据来源**：`html-explainer/references/showcase-mode.md` 的六条设计律。你做纯视觉卡点片时这五条是硬指标。

### B3 可行性再核
想做的 vs 管线真能做的。见 `references/feasibility.md`（含「做不到时的三个替代方案」话术）。

### B4 机械体检
```bash
python <skill>/scripts/spec_review.py --project <项目目录>
```
秒级出结果：字段完整性 / 七项确认是否齐 / 参数取值是否越界 / 单调度五条判据 / 与 `html-explainer` 契约的一致性。退出码 1 = 有 FAIL。

### 产出：`review.md`

**每条问题必须带三样：现象 → 判据 → 具体改法（可执行到参数级）。**
"节奏有点平"是不合格的问题描述；"第 4–7 场 `motion_intensity` 都是 0.5，建议改成 0.45/0.72/0.38/0.65 拉开起伏"才是。

## 4. 阶段 C · 优化（闭环，别省）

成片交付后**必做**，否则这套链路永远停在原地：

1. 问用户三个问题：**哪里跟你想的不一样？哪个镜头你会重来？哪句词是废话？**
2. 把回答归因到**参数层**（不是"这段不好"，而是"`pace:fast` 配 `motion_intensity:0.45` 是矛盾的，下次这种组合直接拦"）
3. 追加进 `references/lessons.md`，格式见该文件表头
4. 如果某条教训能变成**机械可查**的规则，就加进 `scripts/spec_review.py` —— **这是本技能"可优化"的实质**：教训沉淀成闸门，而不是留在某次会话的记忆里

## 7. 纪律（每条都是踩坑换来的）

1. **不替用户拍板。** 记忆里"上次挺好用"不构成这次的选择。
2. **不给开放题。** 弱模型 + 用户说不清 = 必须给候选。开放式问题在这里是缺陷不是礼貌。
3. **A3 之前不许写解说词。** 参数没定就写词，等于用错误的规格生产。
4. **审查要在写词之前。** 简报期改一个词是 0 成本，渲完再改是整片重来。
5. **问题必须可执行到参数级。** 说不出改哪个字段 = 还没诊断完。
6. **复盘要落到闸门。** 能机械查的就写进 `spec_review.py` / `accept.py`，别只写在文档里。
7. **素材与音乐版权、事实数据出处**归 `html-explainer` 管，本阶段只负责指出「这里有风险」。
8. **★ 分段验收是默认姿势，不是可选项。** 每段产出就停下验收，`accept.py` 机械把关；
   前置未过不许越级（越级要显式 `--force` 并留痕）。
9. **下层审查不全绿，不进上层。** 用 10 秒的机器层换掉你几分钟的人眼（见 `aesthetic-review-layers.md`）。
10. **skip 必须写理由。** 明确跳过是选择，静默跳过是事故。
