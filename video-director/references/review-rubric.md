# 审查评分表

> B 阶段用。**每条问题必须三样齐全：现象 → 判据 → 参数级改法。**
> 说不出改哪个字段，说明还没诊断完。
>
> 输出落到项目根的 `review.md`。

---

## 0. 分级

| 级 | 含义 | 处置 |
|---|---|---|
| **FAIL** | 会直接导致返工或成片错误 | **必须改完才开工** |
| **WARN** | 会明显拉低效果但不致命 | 给改法，用户可接受风险 |
| **INFO** | 优化建议 | 记录，不阻塞 |

`spec_review.py` 机械判 FAIL/WARN；人读部分补 INFO。

## 1. B1 自洽性（内部与互相不打架）

| 检查 | 判据 | 级 |
|---|---|---|
| `mood` vs 风格 | `calm` 配故障艺术/电光工作室 → 反 | FAIL |
| `pace` vs 强度 | `fast` 配全片 `intensity < 0.5` → 赶而无力 | WARN |

## 2. B2 单调度体检（**对症"单调"，本表最重要**）

来源：`html-explainer/references/showcase-mode.md` 六条设计律。做纯视觉卡点片时这五条是硬指标。

| # | 判据 | 红线 | 级 | 改法 |
|---|---|---|---|---|
| 1 | **风格数** | < 2 种 = 单调；> 4 种 = 花 | WARN | 补到 3–4 种轮换，或收窄 |
| 2 | **同风格连场** | 连续 ≥3 场同一个 | WARN | 第 3 场强制换（同类内换优先） |
| 3 | **运镜场次比** | **每场 ≥1 次可测运镜**；低于 100% 即 PPT 苗头 | FAIL(<100%) | 每场补 `slowPush`(长镜头) / `camTrack`(有焦点移动) / `whipPan`(快切前)，并让 `__motion(t0,t1)` 报出非零 px |
| 4 | **承接连律** | 相邻场**至少一个元素跨边界继续动**；全片承接数 = 0 = 幻灯片 | FAIL(=0) | 用 `morphBox` / `irisOpen` / `diveInto` / `arcHop` 串场 |
| 5 | **动效强度起伏** | 全片 `motion_intensity` 方差过小（如都 0.5） | WARN | 排起伏曲线，**落差 ≥0.2**；开场高、收尾低 |

### 3 号判据怎么落地（最常被判 FAIL 的一条）

**可测运镜** = 能用 `window.__motion(t0, t1)` 报出屏幕位移 px 的运镜。选型：

| 场景特征 | 用哪个 |
|---|---|
| 长镜头（>3s）内容不动 | `slowPush`（默认 +7%），防"以为卡了" |
| 场内有焦点转移 | `camTrack`（关键帧 `{t,x,y,zoom}`） |
| 硬切前 | `whipPan`（**必须开快门**，否则撕裂跳帧） |
| 撞击瞬间 | `camShake`（确定性 seed） |

**样板改法写法**（照这个颗粒度写，别写"加点运镜"）：
> 现象：第 4/5/8 场 `__motion` 返回 0，无运镜
> 判据：B2-#3 每场 ≥1 可测运镜
> 改法：第 4 场结尾插 `slowPush(t, 3.2, 5.7, 0.06)`；第 5 场改 `camTrack` 关键帧
> `[{t:0,x:0,y:0,zoom:1.06},{t:5.8,x:24,y:-12,zoom:1.0}]`；第 8 场在 6.1s 处加 `whipPan` 且渲染开 `--shutter 180`

## 3. B3 可行性再核

见 `references/feasibility.md`。**凡是"做不到"的，必须给替代方案，不许静默降级。**

| 用户要的 | 常见不可行处 | 处置 |
|---|---|---|
| 真实拍素材 | 管线是代码渲染，不拍实拍 | 给"实拍转 MG"或"改用 HyperFrames/剪映" |
| 2D 角色动画/人脸 | 无角色资产管线 | `anidoodle`（代码画插画）或换工具 |
| 精确复刻某支现成片 | 管线不做逐帧复刻 | 只吸纳配色/字体/时序三层（showcase-mode §3） |
| 4K60 + 满幅照片 | 可以但很慢 | 先确认渲染通道（`--png-fast` / JPEG q95） |
| 复杂 3D | `three.js` 可做，成本高 | 拆成 2.5D 视差，或明确报工时 |

## 4. B4 机械体检

```bash
python <skill>/scripts/spec_review.py --project <项目目录>
```

查：字段完整性 / 七项确认 / 取值越界 / 单调度五判据 / 与 html-explainer 契约一致性。
退出码 1 = 有 FAIL。

## 6. 审查纪律

1. **在写解说词之前跑。** 简报期改一个词 0 成本；渲完再改整片重来。
2. **问题必须可执行到参数级。** "节奏有点平"不合格；"第 4–7 场强度都是 0.5，改成 0.45/0.72/0.38/0.65"合格。
3. **不许只报问题不给改法。** 每一条 FAIL/WARN 都要带参数级处方。
4. **列出"查过没问题的项"。** 否则用户不知道覆盖范围，会重复问。
5. **不要重复 A 阶段已确认的事。** 审查是查一致性，不是重做访谈。
