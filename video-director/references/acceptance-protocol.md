# 分段验收协议

> **原则：每生成一段，就停下来让你验收一段。**
> 不是"做完给你看"，是**逐段签字放行**——每段都有明确的产出物、验收方法、判据、退回成本。
>
> 为什么值得这么做：**改动成本随阶段指数上升**。
> 策划期改一个词 ≈ 0 成本；渲完几千帧再改 = 整片重来。

---

## 0. 全局设计

```
A1 A2 A3 A4 A5   B1        V1      V2      V3     V4     V5     V6     V7    V8    V9
 策划五轮 ──► 机械体检 ──► 解说词 ──► 配音 ──► 分镜 ──► 参考帧 ──► 全帧 ──► 打样 ──► 混音 ──► 全片 ──► 封面
             (0成本)     (低)     (低)    (0)    (30秒)  (中)   (中)   (零重渲) (高)   (低)
    └────────────── video-director ──────────────┘└────────────── html-explainer ──────────────┘
```

**验收记录落在 `acceptance.json`**，由 `accept.py` 管理：

```bash
python <vd>/scripts/accept.py --project . --list            # 看当前进度与下一关
python <vd>/scripts/accept.py --project . --show V2         # 看某一关该验什么
python <vd>/scripts/accept.py --project . --pass V2 --note "音色 OK，第 3 段重音偏重"
python <vd>/scripts/accept.py --project . --fail V2 --note "第 5 段语速太快，重合成"
```

**状态语义**：`pending`（未验）/ `pass`（通过）/ `fail`（打回）/ `skip`（明确跳过，要写理由）。
**前置未过则不许进下一关**（脚本会挡）—— 纸面规则会被静默跳过，必须变成闸门。

## 2. 逐关细则

### A1–A5 · 策划五轮（video-director A 阶段）

**产出**：`creative-brief.md`（一页纸）+ `brief.json` + `consent.json`

**你怎么验收**：读那**一页纸**。它故意写成人话——不是给你看 JSON。

逐节确认：
- §1 意图：观众看完该做什么、发在哪
- §2 参照：像什么、**不像什么**、提取出的三个可执行维度
- §3 **参数表**（核心）：节奏/密度/温度/强度曲线/转场/快门 —— 每行都有"依据"
- §4 七项确认
- §5 可行性：能做到 / 有代价 / 做不到（含替代方案）
- §7 你的确认语句

**判据**：§3 每一行你都能说出"对"或"改成 X"。**改不动也挑不出 = 前面没问够，退回重问。**

**退回成本**：0。改完重跑 `spec_review.py`。

### B1 · 机械体检

```bash
python <vd>/scripts/spec_review.py --project .
```

**判据**：**FAIL 清零**。WARN 可带风险接受（要写进 `acceptance.json` 的 note）。

**特别注意 B2 单调度五判据**——这是你"单调"问题的机械检出点：

| 判据 | 红线 |
|---|---|
| 风格数 | <2 单调 / >4 花 |
| 同风格连场 | 连续 ≥3 场 |
| **运镜场次比** | **必须 100%**（不足即 PPT 苗头） |
| **承接连律** | **全片为 0 = 幻灯片** |
| 强度起伏 | 落差 <0.2 = 平 |

**退回成本**：0。

### V1 · 解说词

**产出**：`narration.json`（每场一句）

**你怎么验收**（两条路，建议都走）：
```bash
# ① 直接读（人读）
cat narration.json
# ② 看时长预估表（数字）
python <skill>/scripts/timeline_build.py --project . --dry-run   # 若有 --dry-run
```

**判据**：
- [ ] **一句一场景**，没有一场塞两个点
- [ ] 字幕块 ≤16 字，切点在语义边界
- [ ] 预估时长落在 A4 定的区间（差 >15% → **加/删句子，别改语速硬凑**）
- [ ] **三类废句已删**：`A 或者不 A` 的同义反复 / 复读标题的自指句 / 鸡汤式留白
- [ ] 每个画面数字都能在 `research/调研.md` 找到出处

**⚠️ 为什么要在这一步卡住**：改词 → 重跑 tts/timeline/subs → **全部 `beats.js` 秒数一起位移**。
虽然帧代码不用改（这是本管线的结构性优势），但所有节拍引用会变。

**退回做法**：改 `narration.json` → 重跑 V1 验收。**此时还未合成配音，成本极低。**

### V2 · 配音（逐段听）★

**产出**：`audio/<id>.mp3` —— **一个场景一个文件**，天然分段验收。

**你怎么验收**：
```bash
# 逐段播放（按你的播放器，或）
ffplay audio/hook.mp3
# 看 manifest 里的时长与节拍
cat audio/audio-manifest.json
```

**判据**（逐段过）：
- [ ] **音色**对（克隆音像不像你 / 设计音合不合调性）
- [ ] **语速**合适（`rate` 调过没有）
- [ ] **断句**自然——特别是 `|` 切块处有没有把语义切断
- [ ] **重音**落在该落的地方（数字、结论、转折词）
- [ ] **含数字的段**：检查字幕块起点有没有偏（VoiceStudio 特有，见下方警告）
- [ ] 无杂音/爆音/截断

**⚠️ VoiceStudio 特有风险**：数字被念成中文（`4479.55` → 「四千四百七十九点五五」），
Whisper 回写的词是中文读法，而 `subs.py` 按**原文**找词 → **含数字的块起点可能偏一点**。
**验收方法**：专门听含数字的段，对照 `beats.js` 看那块的起播秒对不对。

**退回做法**：
```bash
# 只换音色/语速：改 project.json 的 voice/rate → 重跑 tts_voicestudio.py
#   缓存 sig 含"音色+语速+文本"，只重合成受影响的段
# 只改某几段文本：改 narration.json 对应项 → 重跑三条
```
**成本低**——缓存命中，其余段不重复合成。

**逐字卡点片**：若 Whisper 对齐精度不够，这一步就要决定**退回 edge-tts**。

### V3 · 分镜 + 风格编排

**产出**：`script/storyboard.md` + `style-plan.json`

**你怎么验收**：
```bash
cat script/storyboard.md
python <skill>/scripts/style_director.py --project . --dry-run    # 只预览不写盘
```

看 `style-plan.md` 的两个关键列：
- **主风格 / 次风格**：每场套哪个风格 DNA；次风格是否真的只用在局部
- **`why` 字段**：**这场为什么被挑中**（逐条可解释）

**判据**：
- [ ] 每场有**画面 / 主角·尺寸 / 光 / B() 锚点**四列
- [ ] 风格 3–4 种轮换，**没有连续 3 场同一个**
- [ ] 每场有可测运镜（`slowPush`/`camTrack`/`whipPan`）
- [ ] 相邻场有承接（`morphBox`/`irisOpen`/`diveInto`/`arcHop`）
- [ ] 全场末的**全局约束**：贯穿示例、事实清单、高光清单、每章 ≥3 处运镜
- [ ] `why` 里如果出现你不同意的判断，用 `--pin id=style` 钉死

**退回成本**：0（帧还没写）。

**技巧**：不想到 23 个风格里挑？先用 `--allow` 收窄候选池，比如
`--allow frame-build-minimal --allow frame-data-rollup`。

### V4 · 参考帧（**性价比最高的一关**）★

**产出**：4–5 张覆盖全部风格 DNA 的静帧

**你怎么验收**：
```bash
node <skill>/scripts/peek_frame.mjs . hook --at-sec 3.5    # 秒级出图，不渲全片
node <skill>/scripts/peek_frame.mjs . hook --at 100 --guides   # 叠十字中线+字幕禁区线
```

**判据**：
- [ ] 一眼能看出"这是哪种风格"（DNA 对不对）
- [ ] **每帧一个焦点**，主角 ≥170px 或大字 ≥96px，带 accent 柔光
- [ ] 配角不发光；**accent 只给当前重点**
- [ ] 背景只有幕底 + 网格，**无碎屑**
- [ ] 亮底帧已带 `<body class="paper">`（否则白底白字）
- [ ] 底部 80–170px 字幕带**无内容**

**为什么这一关最值**：**风格错了只浪费 30 秒**。
如果等到全部帧写完再发现风格不对，就是几十帧重做。

**退回成本**：低。改参考帧 → 重出图 → 重验。**参考帧定稿后，它同时是各构建组的骨架模板。**

### V5 · 全片静帧

**产出**：全部 `frames/<id>.html` + 三条静态体检全绿

**你怎么验收**：
```bash
# 三条体检（秒级）
python <skill>/scripts/check_beats_refs.py --project .
python <skill>/scripts/lint_frames.py      --project .
node   <skill>/scripts/check_layout.mjs   .
# 抽帧速览
"$PY" <skill>/scripts/qc_check.py --project .     # → out/qc_sheet.jpg
# 占位残留检查（必须为空）
grep -l 占位 frames/*.html
```

**判据**：
- [ ] 三条体检**全绿**（`check_layout.mjs` 的 **ERROR 必须清零**）
- [ ] **无占位帧残留**
- [ ] qc_sheet 肉眼看：一焦点、光跟主角、无碎屑
- [ ] **家族一致的帧**（章节卡、封面对）圆角/字号/曲线是否一致 —— **只有人眼能查**

**退回成本**：中（改帧 + 局部重渲 `--only <id>`，注意 `--only` 只对末场安全）。

### V6 · 打样（前 30 秒）

**产出**：`preview.mp4`

**你怎么验收**：**看片子**。这一步是做完整判断的地方。

```bash
node <skill>/scripts/render_video.mjs . --preview 30 --jpeg --keep-frames
```

**判据**（**风格 / 字号 / 语速 / 节奏在这里一次定稿**）：
- [ ] 开头 3 秒抓不抓人
- [ ] 字号舒服（投屏看，不是贴屏幕看）
- [ ] 语速合适
- [ ] **节奏有没有起伏**——是不是一直同一个强度（这是"单调"的主观检出点）
- [ ] 转场自不自然
- [ ] 字幕与语音对不对得上
- [ ] **明暗切换处的字幕皮肤**（亮底帧的白字能不能看见）

> 亮底字幕皮肤**是渲染期产物，改它 = 整片重渲** —— 所以打样**必须**包含跨明暗切换的那几十秒。

**退回成本**：中。
- 改语速 → 重跑 V1 三条命令（beats 自动刷新，**帧代码不用动**）
- 改配色 → `make_theme.py --use` 只重写 `theme.css`，**帧零改动**
- 改画面结构 → 回到 V4/V5

### V7 · 混音（音效 + 配乐）

**产出**：`audio/mix.wav` + `audio/sfx.json`（cue 表）+ `audio/mix-report.json`

**你怎么验收**：**听**。
```bash
ffplay audio/mix.wav
# 或直接换到成片上听（零重渲）
node <skill>/scripts/render_video.mjs . --audio audio/mix.wav --mux-only
cat audio/sfx.json          # cue 表，可手改
cat audio/mix-report.json   # 时长 / BGM 来源 / cue 数
```

**判据**：
- [ ] **音效贴帧**——每个 `pop`/`tick` 落在对应元素出现的那一刻（±0.05s）
- [ ] **高潮点有 impact**，且不刺耳
- [ ] **说话时 BGM 让位**（有 BGM 时）；间隙恢复自然
- [ ] 音效**不抢人声**（`--sfx-gain` 可调）
- [ ] 响度：`I ≈ −14 LUFS / TP ≤ −1.5`
  ```bash
  ffmpeg -i out/<slug>.mp4 -af ebur128 -f null - 2>&1 | tail -20
  ```

**退回做法**：手改 `audio/sfx.json` 的 cue → 重跑 `audio_mix.py` →
**`--mux-only` 零重渲**换音轨。

**成本：这一类是所有关卡里最低的**——画面一帧不用重渲。

### V8 · 全片

**产出**：`out/<slug>.mp4`

**你怎么验收**：**连看一遍**（别跳）。看的时候记时间码。

**判据**：
- [ ] `out/qc_report.md` 的 **FAIL 清零**
- [ ] 成片与音轨时长差 <0.5s
- [ ] 连看一遍：有没有"这里怎么停了""刚才那个是什么"
- [ ] 结尾不拖沓（这是最常出问题的地方）

**发现问题**：报"几分几秒 + 一句现象"，别重新描述场景：
```bash
python <skill>/scripts/frame_at.py --project . --at 1:23
```
它会给出场景 id / 帧号 / 源文件 / 当刻字幕块 / 三张给视觉模型看的图。

**退回成本：高**。但**局部问题别整片重渲**：
```bash
node <skill>/scripts/render_video.mjs . --only <场景id>    # 只重渲那一场
node <skill>/scripts/render_video.mjs . --mux-only         # 只重合成
```
实测教训：3802 帧全重渲 924s，补渲两段只花 220s。

### V9 · 封面

**产出**：`cover_169.png` + `cover_34.png`（+ 竖版 `cover_916.png`）

**你怎么验收**：
```bash
node <skill>/scripts/cover_build.mjs .       # 出图
node <skill>/scripts/check_cover.mjs .       # ★ 几何实测，FAIL 清零
# 看 out/cover_report.md
```

**判据（封面三要素，缺一返工）**：
- [ ] **大字钩子** ≥96/≥120/≥130px（按画幅），含反差悬念
- [ ] **核心悖论视觉**（两数对照/一升一降/分裂线/一明一暗）—— **不是装饰图形**
- [ ] **信息余量**：四边 ≥96/≥110/左右 ≥90px，无贴边文字
- [ ] 封面文字与**视频首帧钩子同义**
- [ ] 9:16 张：上边距 ≥180px、下边距 ≥160px、**无左右两栏**

**为什么必须跑几何实测**：肉眼只看得出明显问题，**差 20px 的贴边、多出一字的孤行全靠它抓**。

**退回成本**：低。

## 3. 回退路径图（哪一关退回要重跑什么）

| 验关卡 | 退回后必须重跑 | 不必重跑 |
|---|---|---|
| A1–A5 | 只改文档 | 一切 |
| B1 | 只改参数 | 一切 |
| V1 解说词 | tts → timeline → subs | **帧代码**（beats 自动刷新） |
| V2 配音 | tts → timeline → subs | 帧代码 |
| V3 分镜/风格 | style_director → gate_check | 配音、时间轴 |
| V4 参考帧 | 重写参考帧 | 其余帧 |
| V5 全帧 | 改帧 → 三条体检 → 局部重渲 | 配音、混音 |
| V6 打样 | 看回退原因（语速→V2；配色→theme；画面→V4/V5） | — |
| V7 混音 | audio_mix → `--mux-only` | **画面一帧不动** |
| V8 全片 | `--only <id>` 局部重渲 → `--mux-only` | 其余场 |
| V9 封面 | cover_build → check_cover | 成片 |

**记忆法**：**越靠前的关卡，退回越便宜。** 所以前面几关要卡严，后面几关可以松一点。

---

## 4. 批量验收（场景多时）

场景 20+ 时逐个签字太累。**分组验收**：

- **V2 配音**：按章节分组听（`project.json` 的 `chapters`），一组 4–6 段
- **V5 全帧**：按构建组验收（本来就是一组的往往风格一致）
- **V8 全片**：按章节连看，每章停一次

但 **V4 参考帧必须逐个看** —— 它决定后面所有帧的长相。

---

## 5. 纪律

1. **前置不过，不进下一关。** 由 `accept.py` 机械挡，不靠自觉。
2. **`skip` 必须写理由。** 明确跳过是我的选择，静默跳过是事故。
3. **验收意见要落到"哪一段/哪一秒 + 什么现象"。** "感觉不对"无法执行。
4. **WARN 可以带风险接受**，但要写进 `note`——事后好解释。
5. **每关验收完立刻记进 `acceptance.json`**，别攒到最后——攒着就等于没验。
