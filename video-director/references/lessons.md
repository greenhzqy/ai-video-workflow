# 复盘台账（可优化入口）

> **本技能的"可优化"就落在这个文件上。** 每做完一支片子，追加一条。
>
> 规则：
> 1. **归因到参数层**，不是"这段不好"，而是"`pace:fast` 配 `motion_intensity:0.45` 是矛盾的"。
> 2. **能机械查的，立刻写进 `scripts/spec_review.py`** —— 教训沉淀成闸门，而不是留在某次会话的记忆里。
> 3. 只写**可复用的通则**，不写单次事故的流水账。
> 4. 每条都要有**判据**（下次怎么检出）和**处方**（检出后怎么改）。

---

## 格式

```markdown
### L<n> · <一句话通则>
- **症状**：<用户/你观察到的现象>
- **归因**：<参数层的真正原因>
- **判据**：<下次怎么检出——能写脚本就写脚本>
- **处方**：<检出后改什么>
- **首次遇到**：<日期> <项目>
```

## 台账

### L1 · 入口缺访谈 = 全片参数靠猜
- **症状**：成片"单调""像 PPT""跟我想要的不一样"，但改起来无从下手
- **归因**：`brief.json` 只有 `topic/mood/pace/audience/aspect` 五个字段，而**没有任何环节去问用户要什么感觉**；`motion_intensity`、运镜场次、风格轮换全是 agent 猜的
- **判据**：项目里没有 `creative-brief.md`，或 `consent.json` 的 `choice` 字段写得像技术描述而不是用户的话
- **处方**：走 `video-director` 完整 A 阶段，产出三份文件再开工
- **首次遇到**：2026-10-14 用户自述"生成的视频过于单调，缺少动效和图画"

### L2 · 单调度是可机械检出的，不该靠肉眼
- **症状**：看完觉得"平"，但说不出哪里平
- **归因**：五条判据（风格数/同风格连场/运镜场次比/承接连律/强度起伏）全都没被检查过
- **判据**：`spec_review.py` 的 B2 段；运镜场次比 < 100%、承接数 = 0、强度方差过小
- **处方**：按 `review-rubric.md` §2 的处方逐条补
- **首次遇到**：2026-10-14

### L3 · 感受必须翻译成参数，否则无法执行
- **症状**：需求写成"要有高级感""别像 PPT"，做完仍不对
- **归因**：形容词没有落到管线真正读的字段（`mood`/`pace`/`motion_intensity`/`transition_out`/`--shutter`）
- **判据**：`brief.json` 里出现无法映射到旋钮的描述
- **处方**：走 `feeling-to-params.md` §1 主表
- **首次遇到**：2026-10-14

### L4 · 开放题对弱模型近乎无效
- **症状**：问"你想要什么风格"，用户答不出；agent 于是自己拍了板，用户事后不满意
- **归因**：开放式提问把"想清楚"的责任推给了说不清的用户
- **判据**：访谈记录里出现无候选的开放式问题
- **处方**：一律给 2–4 个候选让他**挑**，别让他**想**
- **首次遇到**：2026-10-14

### L5 · 卡点片最常卡错层
- **症状**：卡点片看着"没卡上"，差一点点
- **归因**：画面节拍锚在字幕/时间，而音乐重音是另一套时刻表 —— **两者不同源**
- **判据**：分镜里没有"音乐重音时刻表"，或画面节拍与重音表没有共同来源
- **处方**：先定重音表，再让画面节拍锚上去（详见 `genre-playbooks.md` §3）
- **首次遇到**：2026-10-14（预防性写入，待实战验证）

### L6 · 潜力：把"像什么"提取成三维度
- **症状**：用户给了参照片，agent 试图整体模仿 → 四不像
- **归因**：参照物是整体印象，不能直接执行
- **判据**：策划书里出现"整体像 XX"这种描述
- **处方**：必须提取**三个可执行维度**（如：大留白单焦点 / 冷色低饱和 / 慢速推镜）再交回确认
- **首次遇到**：2026-10-14

### L7 · Windows 上 JSON 必须按 utf-8-sig 读
- **症状**：`brief.json` 报 `JSONDecodeError: Unexpected UTF-8 BOM (decode using utf-8-sig): line 1 column 1`
- **归因**：PowerShell 的 `Set-Content -Encoding UTF8`、记事本"另存为 UTF-8"、Excel 导出都会写 **BOM**；纯 `utf-8` 解码在第 1 列就炸
- **判据**：读任何用户可能手改过的 JSON 时用 `encoding="utf-8"` 而非 `utf-8-sig"`
- **处方**：`spec_review.py` 的 `_load_json` 已改用 `utf-8-sig`（对无 BOM 文件同样正确）。**新增任何读 JSON 的脚本一律照抄**
- **首次遇到**：2026-10-14 开发期实测（`python scripts/spec_review.py` 读 PS 生成的 brief.json）

### L8 · 单调度是可机械检出的，已有实例为证
- **症状**：成片被评价为"单调""像 PPT"，但说不清哪里单调
- **归因**：一支真实的 10 场讲解片，其 `style-plan.json` + `storyboard.md` 实测：**运镜场次比 0/10、承接处 0 处**
- **判据**：`spec_review.py` 的 `B2-camera` / `B2-carry` 两条直接判 FAIL
- **处方**：这正是本技能存在的理由——**旧管线从不检查这两条**，所以问题一路带到成片才被发现
- **首次遇到**：2026-10-14

### L9 · 验收必须是闸门，不能是协议
- **症状**：协议写得再清楚，agent 也会一口气跑到底，用户事后才发现"你没让我验收"
- **归因**：纸面规则会被静默跳过（与 `gate_check.py` 同一个教训）
- **判据**：`accept.py` 的 `prereq_ok` + 产出物存在性检查；越级需显式 `--force` 并记 `forced=true`
- **处方**：任何"必须停下等用户"的环节，都要有一个**退出码非 0** 的机械闸门
- **首次遇到**：2026-10-14 用户要求"每生成一段就让我验收一段"

### L10 · 管线本身是分段友好的，缺的只是协议
- **症状**：以为要做"分段生成"的新能力
- **归因**：其实 `audio/<id>.mp3` **一声一文件**、`frames/<id>.html` **一场一文件** ——
  天然支持逐段产出与逐段验收
- **判据**：验收点直接挂在既有产出物上，无需改动 `html-explainer`
- **处方**：分段验收 = 在既有产出物上**加闸门**，不是重写管线
- **首次遇到**：2026-10-14

### L11 · 改动成本是倒序的，验收顺序要顺着它排
- **症状**：把验收点设在渲染后 → 发现问题时已经太贵
- **归因**：策划 0 成本 → 解说词低 → 配音/混音低（缓存命中 / 零重渲）→ 单场中 → 全片高
- **判据**：验收点排序应让"越早的关卡越严"
- **处方**：`acceptance-protocol.md` 的关卡顺序按此排；V4（参考帧）性价比最高
  （风格错了只浪费 30 秒）
- **首次遇到**：2026-10-14

### L12 · 工具的逻辑要跟场景匹配，不能拿来就用
- **症状**：拿一个高质量口播稿 skill 直接做社交平台短视频，出来的稿子太"重"
- **归因**：`mediastorm-copywriter` 是为 **5–8 分钟长视频**设计的（2500–4500 字 / 黄金七段式 /
  CTA 是「三连 + 那么我们下次再见」）。社交平台是**另一套引擎**：前 3 秒定生死、字数 60–400、CTA 平台原生
- **判据**：文案字数远超平台区间；开场是「大家好 / 今天我们来聊聊」；CTA 说「下次再见」
  （`spec_review.py` 的 B5 段可机械检出）
- **处方**：长视频用飓风逻辑；社交平台必须**压缩成黄金三拍 + 钩子三重奏**（见 `social-hook-engine.md`）。
  **工具越专业，越要看清它的适用场景**——它的"优点"在错配场景里就是"缺点"
- **首次遇到**：2026-10-14

### L13 · 多套参考规则可能直接冲突，必须写明裁决
- **症状**：引入两个 skill 后规则互相打架，不知道听谁的
- **归因**：`mediastorm-copywriter` 要求「结尾升华 + 落一句金句」；
  `humanizer-zh` 要求「删除金句——如果听起来像可引用的语句，重写它」
- **判据**：同一份文案套两套规则时，结尾被删还是被留，取决于场景而非常识
- **处方**：**按场景裁决**——长视频听飓风（金句是记忆点）；社交平台听 humanizer
  （短视频里金句显得说教，掉完播率）。判据：读出来像**演讲结尾**→删；像**随口总结**→留。
  **凡是引入多个参考源，都要写明冲突裁决规则，否则现场随机**
- **首次遇到**：2026-10-14

### L14 · 钩子必须单独成关，不能混在解说词里
- **症状**：钩子问题被当成"文案细节"，在解说词环节顺带看一眼就过了
- **归因**：流量向内容里，**前 3 秒决定 90% 完播率**——钩子的权重不低于整片画面
- **判据**：`accept.py` 的 V0 关卡；`spec_review.py` 的 B5 段（开场禁语/字数/CTA/数字）
- **处方**：V0 独立于 V1（V1 管"怎么切"，V0 管"说什么"），且**前置未过不许写解说词**
- **首次遇到**：2026-10-14
