# 多层审美审查

> 「审美」听着玄，但它可以**分层**——越往下越机械、越便宜；越往上越主观、越贵。
> **核心纪律：下层不全绿，不许进上层。** 否则就是花人眼去看机器该抓的错。
>
> **关键事实**：你现有管线已有 L1/L2/L4/L5（秒级机械层），
> **缺 L3（单调度）和 L6/L7（视觉审美）** —— 这正是 `video-director` 与本文补的。

---

## 0. 八层总表

| 层 | 名称 | 谁执行 | 速度 | 管什么 | 现状 |
|---|---|---|---|---|---|
| **L1** | 契约层 | 脚本 | 秒 | 文本规则（外链字体/色值字面量/墙钟/字幕带压内容） | ✅ 已有 |
| **L2** | 几何层 | 脚本 | 秒 | 遮挡 / 越界 / 侵入字幕带 | ✅ 已有 |
| **L3** | 结构层 | 脚本 | 秒 | **单调度五判据**（风格数/连场/运镜比/承接/强度起伏） | ★ **新增** |
| **L4** | 节拍层 | 脚本 | 秒 | `B()`/`Be()` 能否解析 | ✅ 已有 |
| **L5** | 声画层 | 脚本 | 秒 | 时长差 / 音量 / 字幕块 | ✅ 已有 |
| **L6** | 视觉层 | **视觉模型** | 秒/帧 | 焦点 / 光 / 碎屑 / 版式平衡 | ★ **新增** |
| **L7** | 一致性层 | 模型 + 人 | 分钟 | 家族一致 / 风格轮换协调 / 栅格对齐 | ★ **新增** |
| **L8** | 终审层 | **人** | 分钟 | 好不好看 / 抓不抓人 / 跟想象一不一样 | 不可替代 |

**成本对照**：L1–L5 全跑完 ≈ 10 秒；L6 每帧几秒；L7 几分钟；L8 你连看一遍的时间。
**所以顺序不能反**——用 10 秒的机器层，换掉你几分钟的人眼。

---

## L1 · 契约层（文本规则）

```bash
python <skill>/scripts/lint_frames.py --project .
```

**管八条**：1920×1080 系统字体（禁外部字体）→ 颜色只取 `theme.css` 变量 →
动画只用 GSAP（禁 CSS transition 入场）→ 节拍用 `B()` → 字幕带/进度条带不放内容 →
一场景一焦点 → GSAP 用本地内置 → 主体动画压在 `speech_end` 前。

**它看不见的**：几何。元素全叠在一起它也全绿。

---

## L2 · 几何层（唯一能抓"难看但合规"的机械层）

```bash
node <skill>/scripts/check_layout.mjs .
```

| 级别 | 内容 |
|---|---|
| **ERROR** | 侵入字幕禁区 / 出画 / **文字被遮挡** / 文字重叠 |
| WARN | 越安全边 / 文字压色块 / 色块重叠 |
| INFO | 疑似未对齐 |

**判据：ERROR 必须清零。** 量的是**字墨范围**（Range 逐行），不是元素框——这点很关键。

**⚠️ 铁律：一个几何体只准有一个坐标系。**
SVG 图元与 HTML 部件混用两套基准 → 元素看着"差一点点"，反复对齐都对不上
（实测踩过的坑：「蓝点没落在射线汇聚点上」）。

**⚠️ 它抓不到的**：家族不一致（圆角/字号/曲线四种写法）—— 几何全对，就是难看。那要 L7。

---

## L3 · 结构层（单调度五判据）★ 新增

```bash
python <vd>/scripts/spec_review.py --project .
```

这是**治"单调"的机械层**，也是旧管线完全缺失的一层。

| # | 判据 | 红线 | 为什么 |
|---|---|---|---|
| 1 | 风格数 | <2 单调 / >4 花 | 一片一模板 vs 一场一模板 |
| 2 | 同风格连场 | 连续 ≥3 场 | 观感上"又来了" |
| 3 | **运镜场次比** | **必须 100%** | 不足即 PPT 苗头——静止画面连续出现 |
| 4 | **承接连律** | **为 0 = 幻灯片** | 相邻场无元素跨边界 = 一组画面而非一条动作链 |
| 5 | 强度起伏 | 落差 <0.2 = 平 | 全片一个强度 = 没有呼吸 |

**3 与 4 是核心**。判据来源：`html-explainer/references/showcase-mode.md` 六条设计律。
**判据 4 成立时，即使每拍只做一个动作，全片也不会读成幻灯片。**

**✅ 实测证据**：拿一支真实的 10 场讲解片跑，抓出 **运镜 0/10、承接 0 处** ——
这正是主观上"单调、像 PPT"的量化根因。

---

## L4 · 节拍层

```bash
python <skill>/scripts/check_beats_refs.py --project .
```

**为什么必须单独一层**：`B()` 是**前缀匹配**，失配**只在渲到那一帧时才抛错** ——
前面几百帧白渲。本层把它提前到构建期，失配时打印**该帧可用块列表**。

---

## L5 · 声画层

```bash
python <skill>/scripts/qc_check.py --project .
```

管：成片与音轨时长差（<0.5s）/ 音量 / 字幕块合法性 / 抽帧速览图。

**字幕三纪律**（都在这一层）：中文 ≤16 字/块、无标点、单帧硬切、每块 ≥0.6s、末块跟语音消失。
**小数点不算标点**（`2.4%` 上屏幕必须是 `2.4%`，削成 `24%` 是差一个数量级的**假数字**）。

---

## L6 · 视觉层（视觉模型看帧）★ 新增 — 这里开始才是真"审美"

**前五层全绿 ≠ 好看。** 前五层只保证"没错"，不保证"好看"。

**怎么做**：

```bash
# ① 定位到要看的帧
python <skill>/scripts/frame_at.py --project . --at 1:23
#    → 给出场景 id / 帧号 / 当刻字幕块 / 三张图（整帧 + 底部禁区带 + 场景终态帧）

# ② 或直接抽单帧
node <skill>/scripts/peek_frame.mjs . <帧id> --at-sec 3.5,12 --guides
```

**然后让带视觉的模型看那几张图**（这一步是**关键**：只用文字描述"蓝点没在中间"定位不到，
**看图能直接读出偏了多少、偏哪个方向、被谁压住**）。

### L6 检查清单（逐帧过）

| # | 项 | 判据 |
|---|---|---|
| 1 | **焦点唯一** | 一帧只有**一个**视觉焦点。同屏两个平级重点 = 不合格 |
| 2 | **主角色量** | 主角 ≥170px 或大字 ≥96px，且**带 accent 柔光** |
| 3 | **配角不发光** | 光只跟主角；配角有光 = 抢焦点 |
| 4 | **accent 只用在此刻重点** | accent 撒多了 = 没有重点 |
| 5 | **背景干净** | 只有幕底 + 网格，**无碎屑** |
| 6 | **底部禁区** | 字幕带 80–170px 无内容、进度条带 0–12px 无内容 |
| 7 | **版式平衡** | 视觉重心不歪、不留难看的大空 |
| 8 | **文字可读** | 文字 ≥22px；亮底用 `--accent-on-paper`（`--accent` 在白底对比度不足） |
| 9 | **亮底皮肤** | 亮底帧字幕层是否已换肤（白字落米白 = 看不见） |

**⚠️ 先看终态，再看中途**：
中途帧的入场动画可能还没走完，元素位置**本来就该**和终态不同——单看分不清"代码错"还是"动画错"。
**终态也错 = 布局本身错了；只有中途错 = 动画时序问题。**

## L7 · 一致性层（跨帧）★ 新增

**单帧看都对，连着看还是丑 —— 这一层管这个。**

| # | 项 | 判据 | 谁查 |
|---|---|---|---|
| 1 | **家族一致** | 章节卡 01/04…04/04、封面对、系列数据卡：**圆角/字号/滑入曲线必须一模一样** | 人眼（机器抓不到） |
| 2 | **风格轮换协调** | 相邻两场的风格是不是"同一条片子里"的（不是拼盘） | 人眼 |
| 3 | **栅格对齐** | 跨场元素是否落在同一套网格上 | 人眼 + `--guides` |
| 4 | **节奏曲线** | 强度是否真的形成起伏（对照 L3 判据 5 的数字） | 模型 |
| 5 | **视觉语法一致** | 同类信息用同类画面（讲数据用数据风格，讲原理用概念图） | 模型 |

**做法**：把同一组的帧**并排成 contact sheet** 看，比逐张翻更容易发现不一致。

**纪律**：**需要"家族一致"的帧一律主 agent 亲自写**，或先给一份定稿成品要求逐条照抄 ——
派给并行 agent 必然是四种写法，而这种不一致**任何自动体检都抓不到**。

---

## L8 · 终审层（人，不可替代）

**连看一遍，别跳。** 看的时候记时间码。

| # | 项 | 你在判什么 |
|---|---|---|
| 1 | **前 3 秒** | 抓不抓人（决定 90% 的完播率） |
| 2 | **连贯** | 有没有"这里怎么停了""刚才那个是什么" |
| 3 | **节奏** | 有没有喘不过气 / 有没有拖沓 |
| 4 | **结尾** | 是不是拖沓（最常出问题的地方） |
| 5 | **整体** | 跟你脑子里那个**一样不一样** |

**第 5 条只有你能判。** 前七层的目标是**把明显的问题全挡在前面，让你的人眼只花在"像不像你要的"上**。

**发现问题**：报"几分几秒 + 一句现象"：
> 例：`1:23 右下角示意图里小黑点没在射线汇聚点上，偏左上`

然后 `frame_at.py` 落到那一帧 → L6 看图 → 改 → 重跑 L1/L2 → 局部重渲 → 回到同时间点复核。

## 1. 各层与验收点的对应

| 验收点 | 该跑哪几层 |
|---|---|
| B1 机械体检 | **L3** |
| V3 分镜 | L3（读 style-plan 判据） |
| V5 全帧 | **L1 + L2 + L4** → 全绿后进 L6 |
| V6 打样 | L6 + L7（看片子） |
| V8 全片 | **L5** + L8 |
| V9 封面 | 封面专属几何实测（`check_cover.mjs`） |

## 2. 一键全跑（L1–L5）

```bash
$PY=<venv python 绝对路径>; S=<skill>; VD=<vd>
"$PY" $S/scripts/check_beats_refs.py --project .     # L4
"$PY" $S/scripts/lint_frames.py      --project .     # L1
node   $S/scripts/check_layout.mjs   .               # L2
"$PY" $VD/scripts/spec_review.py     --project .     # L3
"$PY" $S/scripts/qc_check.py         --project .     # L5（需已有成片/帧）
```

**前四条秒级，且全在渲染之前** —— 这是最划算的顺序：
**用 10 秒的机器层，换掉你几分钟的人眼。**

---

## 3. 纪律

1. **下层不全绿，不进上层。** 用机器能查的东西去耗人眼 = 浪费。
2. **人眼只花在"像不像你要的"上**（L8 第 5 条），这是任何机器层替代不了的。
3. **发现问题必须落到"几分几秒 + 现象"**，才能进 `frame_at.py` 的定位闭环。
4. **每层都有它看不见的东西**：L1 看不见几何、L2 看不见家族一致、L3 看不见风格协调 ——
   **知道边界比会用更重要**。
5. **审美审查不是最后一步**，是**每段验收点都跑对应层**（见 §1 对照表）。
