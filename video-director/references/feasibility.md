# 可行性判定

> 「确保能实现我想要的效果」——这一节就是干这个的。
> **凡是做不到的，必须给替代方案，不许静默降级**（用户事后才发现 = 最坏的结果）。

---

## 1. 管线能力边界（html-explainer v2.0）

### ✅ 强项（放心承诺）

| 能力 | 说明 |
|---|---|
| 代码渲染的 MG 画面 | HTML/CSS/GSAP，1920×1080 或竖版，确定性逐帧 |
| 音画同步 | 词级字幕对齐、`B()` 节拍锚定到吐字时刻 |
| 40+ 动效词汇 | `assets/motion.js` 五组：enter/carry/contact/camera/ambience |
| 23 种画面风格 | 风格目录 + 主题驱动编排（`style_director.py`） |
| 配音 | edge-tts（免费）/ 火山引擎 2.0（需 Key） |
| 音效 + 可选 BGM | 9 种程序化音效 + 闪避 + 响度归一 |
| 多画幅封面 | 16:9 / 3:4 / 9:16 **各自独立排版**（不是裁切） |
| 画质档位 | 1080p30 → 4K60 + 快门运动模糊 |
| 长片 | 分章、并行构建、断点续渲 |

### ⚠️ 有条件（要主动报成本）

| 需求 | 条件 |
|---|---|
| 满幅照片 | 渲染变慢（PNG 582ms/帧）→ **必须换通道** `--png-fast`(4.4×) 或 `--jpeg q95`(13×) |
| 4K60 终稿 | 原始工作量约 1080p30 的 8–12× |
| 复杂 3D | three.js 可做，但拆成 2.5D 视差成本低得多 |
| 长片（>8min） | 分章 + 并行 agent，1–3 小时量级 |

### ❌ 做不到（要立刻说，并给替代）

| 用户可能想要的 | 为什么不行 | 替代方案 |
|---|---|---|
| 真人出镜 / 实拍素材 | 管线是代码渲染，不拍不剪实拍 | ① 改用剪映/HyperFrames 剪实拍 ② 实拍转 MG 包装（`talking-head-recut` 那一路） |
| 精密 2D 角色动画 / 人脸表情 | 无角色资产与绑定管线 | `anidoodle`（代码画插画，32 种风格，能保持角色一致） |
| **逐帧 1:1 复刻某支现成片** | 管线不做逐帧复刻 | ① 只吸纳配色/字体/时序三层（showcase-mode §3）② 要真复刻走 `claude-motion-design` 的 remake 模式 |
| 写实电影级画面 / 照片级 | 代码绘制做不出写实 | 引入图像模型（Nano Banana 系 skill）生成图，再代码包装 |
| 真实音色克隆 | TTS 不克隆 | edge 多音色 / 火山音色库；或用户自录音频导入 |
| 交互式 / 可点击 | 输出是 MP4（`/slideshow` 那类才有交互） | 明确告知，或改交付网页版 |
| 保证「爆款」 | 没人能保证 | 只说清可控项（前 3 秒钩子、封面、节奏），别承诺效果 |

## 2. 三段式话术（照这个说，别绕弯）

> **第一段 · 能做到的**：
> 「你要的 ①<…> ②<…>，管线完全能做到，而且有现成的 <风格/动效/脚本> 支撑。」
>
> **第二段 · 有条件的**：
> 「③<…> 能做，但代价是 <具体成本>。两个选择：<A 方案> 或 <B 方案>。」
>
> **第三段 · 做不到的**：
> 「④<…> 这条管线做不到，原因是 <具体原因>。我建议改成 <替代 A> 或 <替代 B>，你选。
> 如果你一定要 ④，那我们得换工具 —— 我可以告诉你换成什么。」

**禁止的说法**：
- ❌「应该可以吧」——没有"应该"，要么可以要么不行。
- ❌ 静默按能做到的做，等用户看到成片才发现。**这是最坏的结果。**
- ❌ 「这个很难」——难不是信息。**给出成本数字和替代方案才是。**

## 3. 判定自查（A5 轮收尾逐条过）

- [ ] 用户要的每一条，都归到了 ✅ / ⚠️ / ❌ 三类之一，**没有漏项**
- [ ] ⚠️ 类都给了**具体成本数字**（不是"有点慢"）
- [ ] ❌ 类都给了**至少两个替代方案**
- [ ] 用户明确知道**哪些被降级了**
- [ ] 没有对「效果好不好 / 会不会火」做承诺
